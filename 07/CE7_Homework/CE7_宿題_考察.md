# クリティカル・エンジニアリング 第7回 宿題

氏名：【要記入】　学籍番号：【要記入】

## 課題

本日作成した簡易ビート検出プログラムについて、複数の楽曲を試し、検出結果が妥当な場合と妥当でない場合の傾向を考察する。また、閾値係数、積分幅（2乗和のサンプル数）、リフラクトリ期間のうち、どの値の影響が大きそうかを述べる。

## 1. 方法

- プログラム：`CE7_4bit_dynTh_Ref`（22050 Hz / 4 bit）と `CE7_8bit_dynTh_Ref`（11025 Hz / 8 bit）。授業で完成させた、動的閾値とリフラクトリ期間による判定を使う。
  - 平均エネルギー：`averageEnergy += AVERAGE_ALPHA * (energy - averageEnergy)`（1次 IIR、τ = 1.0 s）
  - 判定：閾値 `THRESHOLD_FACTOR * averageEnergy` を下から上へ超え、かつ前回の検出から `REFRACTORY_TIME` が経過していればビート候補とする
- 基準設定：閾値係数 2.0、積分幅 256 サンプル（4 bit 版）／128 サンプル（8 bit 版）、いずれも 11.6 ms。リフラクトリ期間 200 ms
- 楽曲：配布音源 6 曲
  - ドラムパターン：Pattern1〜3（各 48 s。自己相関と検出間隔から 120 BPM と推定。48 s は 4/4 拍子で 24 小節）
  - 楽曲：StratoS（32 s）、techno-trance（30 s）、northside-drive（70 s）
- 評価の指標：1 秒あたりの検出数、検出間隔の中央値、150 ms 未満の検出間隔の割合（連続検出の目安）、5 秒ごとの検出数
- パラメータは基準設定から 1 つずつ変えた
- 数値は、Processing 側（Mono 化 → LPF → ダウンサンプリング → 量子化 → 4 bit パッキング）と Arduino 側の処理を、同じ式で Python 上に再現して計算した（`beat_sim.py`）。【要記入：実機で内蔵 LED と Processing のグラフ（赤線）を観察した結果と、計算結果との違い】

## 3. 考察

### 3.1 検出結果が妥当な場合

**打楽器が他の音より十分大きい音源では、ほぼ正しくビートを捉えられる。** Pattern1 では、検出間隔の中央値が 499 ms で、120 BPM の 1 拍（500 ms）と一致した。検出は 1 秒に 2.00 回で、拍ごとに 1 回ずつ、ほぼ等間隔だった（間隔の変動係数は 0.01〜0.07）。Pattern2 は 1 秒に 2.5 回で、1 小節あたり、4 つの拍に加えて裏拍（8 分音符の裏）の位置で 1 回検出していた。Pattern3 も 1 小節に 5 回検出したが、裏拍の位置での検出を含み、検出のない拍もあった。自己相関で最も強い周期も 750 ms（付点 4 分音符）だったので、シンコペーションを含むパターンだと考えられる。どちらも、スライドにあるバスドラの裏打ちのようなアクセントを拾っていると考えられ、表拍ではないが、音のイベントとしては正しく検出している。【要記入：実際に聴いて、裏の位置に強い音があるか確認】

これらの音源では、短時間エネルギーの上位 5 % の値が平均の 4.5〜7.3 倍ある。閾値係数 2.0 よりずっと大きいので、閾値係数を 1.6〜3.0、積分幅を 128〜1024 の範囲で変えても、検出数はほとんど変わらなかった（Pattern1 で 96〜97 回、Pattern2 で 120〜121 回）。

また 8 bit 版では、音量を 1/10 にしても検出数がほぼ変わらなかった（Pattern2：120 → 120 回、northside-drive：147 → 143 回）。閾値が「その曲の最近の平均音量の何倍か」で決まるので、曲ごとの音量の違いは動的閾値が吸収できている。

### 3.2 検出結果が妥当でない場合

1. **打楽器以外の音も大きい楽曲（StratoS、techno-trance、northside-drive）**
   検出間隔のばらつきが大きく（4 bit 版で変動係数 0.34〜0.85）、間隔の中央値（300〜480 ms）も一定の拍の長さに定まらなかった。これらの曲では、エネルギーの上位 5 % の値が平均の 2.3〜2.7 倍しかなく、閾値係数 2.0 に近い。そのため、ベースやボーカル、シンセの音量変化でも、閾値を超えたり超えなかったりする。スライドで指摘された「大きな音すべてに反応する」問題にあたる。【要記入：LED がボーカルやスネアで光っているかどうか】

2. **打楽器が目立たない区間**
   techno-trance の 25 s 以降は、4 bit 版で検出が 0 回になった（8 bit 版でも 2 回）。この区間はエネルギーの変動が小さく、上位 5 % の値が平均の 1.22 倍しかないため、閾値をほとんど超えない。northside-drive でも 35〜50 s の区間では、5 秒あたりの検出が 2〜4 回に減った（多くの区間では 12〜14 回）。【要記入：聴いて、ドラムが抜ける区間かどうか確認】平均との比だけで判定しているので、曲の構成が変わると検出の傾向も変わる。

3. **1 つの音で何度も検出する（リフラクトリ期間がない場合）**
   リフラクトリ期間がないと、検出間隔の 18〜71 % が 150 ms 未満になった。Pattern1 では、拍の検出の約 35 ms（3 ブロック分）後に、もう一度検出が起きていた。1 つのアタックの中でエネルギーが揺れて、閾値を 2 回またいでいると考えられる。

4. **再生開始の直後**
   `averageEnergy` の初期値が 0 で、時定数が 1 s なので、閾値が曲の平均に追いつくまでの最初の約 0.7 s は閾値が低すぎる。そのため Pattern1 でも、最初の 2 回の検出間隔は約 250 ms で、8 分音符（ハイハット）まで拾っていた。

5. **4 bit 版で静かな曲を扱う場合**
   音量を 1/4 にすると、4 bit 版では量子化後の値が 4 種類しか残らなかった。検出数は northside-drive で 145 → 12 回、StratoS で 62 → 21 回に減った。動的閾値そのものは音量の違いに強いが、4 bit 量子化で小さな音の変化が消えてしまうので、静かな曲は 4 bit 版では検出しにくい。

### 3.3 どのパラメータの影響が大きいか

- **閾値係数**：ドラムパターンではほとんど影響しないが、楽曲では影響が非常に大きい。1.6 から 2.5 に上げると、techno-trance は 79 → 7 回、StratoS は 90 → 43 回に減った。曲ごとの「ピークが平均の何倍か」（上で見た 2.3〜2.7 倍）を閾値係数が超えると、検出が急になくなる（techno-trance：2.2 で 33 回、2.5 で 7 回）。最適な値が曲ごとに違い、少しのずれで結果が大きく変わる。
- **積分幅**：楽曲では、閾値係数と同じくらい影響が大きい（128 → 512 で、StratoS は 104 → 36 回、techno-trance は 80 → 26 回）。積分幅を長くすると、短いアタックが平均に埋もれてピークが目立たなくなるので、閾値係数を上げたのと似た効果になる。さらに、検出位置の時間分解能も粗くなる（11.6 ms → 23.2 ms）。
- **リフラクトリ期間**：「あるかないか」で、連続検出の有無がはっきり変わる（3.2 の 3）。ただし、値を大きくしすぎると本来の音も見逃す。拍の間隔（120 BPM なら 500 ms）以上にすると、検出が半分になった（Pattern1：500 ms で 97 → 51 回）。裏拍までの間隔（250 ms）を超えると、裏拍の位置の検出も落ちた（300 ms で、Pattern2 は 121 → 96 回、Pattern3 は 121 → 73 回）。適切な範囲は、1 つの音の中での揺れ（数十 ms）より長く、検出したい最短の音の間隔（ここでは約 250 ms）より短い範囲になる。これは曲の音色にはあまりよらず、テンポで決まる。

以上から、**最も影響が大きいのは閾値係数**だと考える。積分幅も同じくらい影響するが、閾値係数は曲ごとにピークと平均の比が違うため、同じ値でも、ある曲では検出しすぎ、別の曲ではほとんど検出しない、ということが起きる。リフラクトリ期間は、誤検出を減らすためには欠かせない。しかし、150〜250 ms 程度にしておけば曲によらず同じように働くので、調整が難しいのは閾値係数（と積分幅）のほうである。

### 3.4 改善案

- バスドラムの帯域（低域）だけのエネルギーで判定して、ボーカルやシンセへの反応を減らす
- 閾値を「平均の何倍」ではなく「平均＋k×標準偏差」にして、ピークの目立ち具合が違う曲でも同じ基準で判定できるようにする
- `averageEnergy` の初期値を最初の数ブロックの平均にして、再生開始直後の誤検出を減らす
